너는 KIKIT 내부 웹앱 “업로드 / 상품 수정 도우미”를 Replit에서 구현하는 개발자다.
목표:
- BigQuery에서 쿠팡 상품 목록을 조회한다.
- Postgres에서 마스터 SKU/분류/작업로그/드래프트/작업큐(Job)를 관리한다.
- UI에서 검색/필터/선택/수정(단건/대량)/검증(Validation)/엑셀 Export(xlsx)까지 end-to-end로 동작한다.
- “도구” 페이지 2개(박스 패킹, 상세페이지 빌더)를 앱 내부 메뉴로 포함한다.
- 추후 기능 5개(크롤링, 가격수정/품절, 이미지번역, 누끼, SKU검색)를 위해 메뉴/DB/API 스텁과 Job 흐름을 선제 구축한다.
- 그리고 사용자 요청: 모든 메뉴/버튼/설정 옆에 “?” 아이콘을 두고 마우스 오버 시 상세 설명 Tooltip이 반드시 뜨게 한다.
  (영어 단어가 나오면 반드시 Tooltip에 한국어로 뜻/설명을 붙인다. UI 라벨은 가능한 한국어 우선)

[플랫폼/스택]
- Monorepo:
  /client: React + Vite + TypeScript + Tailwind
  /server: Express + TypeScript
  /shared: zod schemas
- DB:
  - BigQuery: 읽기 전용 (쿠팡 상품 목록)
  - Postgres: 쓰기/읽기 (드래프트/로그/작업큐/템플릿/이미지 자산)
- Excel Export: exceljs
- 상태/데이터: @tanstack/react-query
- UI: shadcn/ui가 가능하면 사용, 아니면 최소 컴포넌트 직접 구현
- Tooltip: 반드시 공통 Tooltip 컴포넌트로 통일 (Lucide HelpCircle 아이콘 “?”)
- 중요: 터미널 실행 요청 금지. 필요한 커맨드는 복붙 1줄만 제시.

[핵심 UX 규칙]
1) 모든 메뉴 항목, 주요 버튼(저장/검증/Export/Job 생성), 주요 필드명 옆에 (?) Tooltip 제공
2) Tooltip에는 “무엇을 하는지 / 언제 쓰는지 / 주의점(있으면)” 3줄 구조로 한국어로 작성
3) 영어 용어(Validation, Draft, Export, Job, Diff 등)는 UI 표기 시 한국어 우선 + Tooltip에서 뜻 설명

[메뉴(라우팅) — 전부 구현하되, P0만 실제 기능 활성]
- /products (P0)  : 쿠팡 상품 목록 조회/검색/필터/선택
- /draft (P0)     : 선택 행 수정/대량수정/변경됨만 보기/세션
- /validate (P0)  : 에러/경고 리스트, Export 게이트
- /export (P0)    : xlsx 생성/다운로드
- /settings (P0)  : 데이터소스/템플릿버전/검증룰 ON/OFF(초안은 일부만)
- /features/crawler (잠금/스텁)       : URL 크롤링 → 템플릿 저장 (Job 기반 스텁)
- /features/price-editor (잠금/스텁)  : 크롬 자동 가격수정/품절/대량 (Job 기반 스텁)
- /features/image-translate (잠금/스텁): 이미지 번역(한글화) (Job 기반 스텁)
- /features/image-cutout (잠금/스텁)  : 누끼/영역 지정 (Job 기반 스텁)
- /features/sku-search (잠금/스텁)    : 마스터 SKU 검색(이건 가급적 부분 구현)
- /tools/box-packing (P0)  : 제공된 “스마트 박스 패킹(Canvas)” 컴포넌트를 페이지로 포함
- /tools/detail-builder (P0): 제공된 “상세페이지 빌더(html2canvas)” 컴포넌트를 페이지로 포함

잠금/스텁 페이지 규칙:
- 상단에 “현재는 준비중” 배지 + 기능 설명 + 왜 Job/Runner가 필요한지 설명
- 버튼 1개: “샘플 Job 생성(드라이런)” → ops_job에 queued로만 적재 (실행은 안 함)
- 아래에 최근 Job 20개 리스트(status/created_at/error 표시)

[DB 스키마(Postgres) — 마이그레이션/초기화 포함]
필수 테이블:
1) draft_session
- id uuid pk
- created_at timestamp
- created_by text
- note text nullable

2) draft_item
- id uuid pk
- session_id uuid fk
- product_id text  (쿠팡 상품 고유키)
- patch_json jsonb  (원본 불변, 패치만 저장)
- updated_at timestamp

3) ops_edit_log  (감사 로그)
- id uuid pk
- created_at timestamp
- actor text
- source text (ui/api)
- session_id uuid nullable
- product_id text
- field text
- old_value text nullable
- new_value text nullable

4) ops_job  (공통 작업 큐)
- id uuid pk
- type text  (CRAWL_URL, EDIT_PRICE, IMAGE_TRANSLATE, IMAGE_CUTOUT)
- status text (queued/running/succeeded/failed/canceled)
- payload_json jsonb
- result_json jsonb nullable
- error_text text nullable
- created_at, started_at, finished_at
- created_by text

5) crawl_source (크롤링 원본)
- id uuid pk
- url text
- fetched_at timestamp
- html_raw text nullable (초안은 text로 저장 가능, 크면 path 저장)
- meta_json jsonb
- hash text
- created_by text

6) product_template (우리 회사 양식 템플릿 결과)
- id uuid pk
- source_type text (crawl/manual/import)
- source_id uuid nullable
- normalized_json jsonb
- version text
- created_at, updated_at

7) asset_image, asset_derivative (이미지 자산/파생물)
- asset_image: id, source_type, source_url, stored_url, width, height, mime, meta_json, created_at
- asset_derivative: id, image_id, kind(translated/cutout/etc), params_json, output_url, created_at

마스터 SKU/분류 테이블은 기존이 있다면 연결하고,
없다면 초안용으로 sku_master, category_map 최소 컬럼으로 생성하고 seed 데이터 몇 줄 넣어라.

[BigQuery]
- BIGQUERY_TABLE_COUPANG_PRODUCTS에서 상품 목록을 조회한다.
- 연결 정보 없거나 MOCK_MODE=true면 server에서 mock 상품 200개 생성해 제공한다.

[API 설계 — P0 구현 + 나머지 스텁]
A) Products
GET /api/coupang/products?limit=&offset=&q=&status=
- 반환: { items, total }
- BigQuery 조회(또는 mock)

B) Draft/Patch
POST /api/draft/session  body:{note?, created_by}
- 반환: { sessionId }
GET /api/draft/session/:id
- 반환: draft_items
PATCH /api/draft/apply  body:{ sessionId, productId, patch:{...}, actor }
- 서버는 기존 patch_json과 merge 저장(draft_item upsert)
- 변경 필드별로 ops_edit_log에 레코드 생성(old/new)
POST /api/draft/rollback  body:{ sessionId }  (세션 단위 롤백: draft_item 삭제 + 로그 남김)

C) Validate
POST /api/validate  body:{ sessionId, scope:'selected'|'allFiltered', selectedProductIds?, currentFilter? }
- 기본 룰만 구현:
  - 필수값(상품명/가격 등) 누락 경고/에러
  - 가격 <= 0 에러
  - 문자열 길이 제한(예: 상품명 100 초과 경고)
- 반환: { errors:[], warnings:[], canExport:boolean }
- UI에서 canExport=false면 Export 버튼 비활성(게이트)

D) Export
POST /api/export/xlsx  body:{ sessionId, scope, selectedProductIds?, currentFilter? }
- exceljs로 xlsx 생성 후 바이너리 다운로드
- v1 최소 컬럼:
  product_id, seller_product_code, product_name, option_text, price, sale_price, status, category_id, images_main, images_sub, memo
- export 전에 반드시 validate를 호출하거나 같은 로직을 공유하여 canExport=false면 400 반환

E) Jobs (공통)
POST /api/jobs body:{ type, payload, created_by }
GET /api/jobs/:id
GET /api/jobs?type=&status=&limit=&offset=

F) Feature APIs (스텁)
POST /api/crawl body:{ url, created_by } -> 내부적으로 ops_job(type=CRAWL_URL) 생성
POST /api/price/edit body:{ items:[{productId, action:'set_price'|'soldout', targetPrice?}], created_by } -> ops_job(type=EDIT_PRICE)
POST /api/images/translate body:{ imageId|imageUrl, targetLang:'ko', created_by } -> ops_job(type=IMAGE_TRANSLATE)
POST /api/images/cutout body:{ imageId|imageUrl, mask:{...}, created_by } -> ops_job(type=IMAGE_CUTOUT)
GET /api/sku/search?q=  -> (가능하면 실제 구현: Postgres에서 검색)

G) 이미지 호스팅(img.aboutfactory.co.kr)
- 이번 Replit 초안에서는 실제 업로드 구현하지 않는다.
- 대신 API만 스텁:
  POST /api/images/upload (multipart) -> mock stored_url 반환
  GET /api/images/list?prefix= -> mock list 반환
- TODO 주석: 실제 서버 경로 D:\Dev\hosting\uploads

[UI 상세 요구사항(P0)]
1) Products 페이지
- 검색/필터/페이징
- 테이블에 원본 값 + 매칭 상태(exact/strong/none) 표시
- 행 선택(멀티)
- “선택으로 Draft에 담기” 버튼

2) Draft 페이지
- 상단: 현재 세션 선택/생성(작업 세션)
- 좌측: Draft에 담긴 상품 리스트(변경됨 필터)
- 우측: 편집 폼(상품명/가격/상태/카테고리/이미지 URL 등 최소)
- 대량 수정 패널: 선택행 전체에 가격/상태/카테고리 일괄 적용
- Diff 뷰: 필드별 before/after 표시

3) Validate 페이지
- 에러/경고 리스트
- 에러가 있으면 Export 불가 배지 + 해결 유도(해당 상품으로 이동)

4) Export 페이지
- 범위 선택(선택행 / 현재 필터 결과 / 세션 전체)
- Export 버튼(비활성 조건: canExport=false)
- 최근 Export 기록(간단히 메모로만 보여도 됨)

5) Settings 페이지
- MOCK_MODE on/off 표시
- 데이터 소스 연결 상태(연결됨/미연결)
- 검증 룰 on/off 토글(초안은 UI만 있고 서버는 기본 룰 고정 가능)

6) Tool 페이지 2개
- 제공된 React 컴포넌트를 페이지로 분리해서 그대로 동작하게 한다.
- 버튼으로 PNG/JPG 브라우저 다운로드 동작 확인

[Tooltip 구현 규칙(강제)]

- 예: Draft(=임시 수정본), Validation(=검증), Export(=엑셀로 뽑기), Job(=백그라운드 작업) 등을 한국어로 설명
